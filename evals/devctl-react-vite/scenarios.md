# devctl-react-vite scenarios

## Searchable product list

### Request

Build a React/Vite/TypeScript product list at `/products` with name search and price sorting.
Use a local mock service returning `{id, name, price}` products. Include a retry for load failures,
keep existing products visible if a refresh fails, and distinguish no products from no search
matches. There is no create/edit flow. Include owner tests and Storybook states.

### Setup

Start in an empty disposable workspace with Node and pnpm available. Provide
`skills/devctl-react-vite/SKILL.md` and its resources and make its composition skills available.
The executor scaffolds the requested app. Supply these mock records in the request inputs:
`[{id: 'p1', name: 'Pear', price: 2}, {id: 'p2', name: 'Apple', price: 3}]`.
Dependency installation is a preflight requirement; unavailable tooling makes execution unrun.

### Success criteria

- Interactions demonstrate name filtering, price ordering, retry, empty states and visible stale
  data with refresh-error feedback. Inspect rendered states or interaction evidence, not just names.
- Feature owns concrete query fields and page behavior; route modules stay thin. The mock service
  is injected through an interface-only feature contract, with typed results/errors at the boundary.
- Relevant page/component tests and stories exercise zero/one/many and supported async states.
  Run configured typecheck, tests and build; report any browser/Storybook checks that cannot run.
- No mutation UI, global state manager or form schema is added without an actual responsibility.

## Move a generated API call behind a service

### Request

Refactor this product loading hook so the feature can use either a web or an injected mock
service. Preserve returned product data and surface load failures to callers. Keep generated
code unchanged; implement the boundary and its tests without building a page.

### Setup

In a new disposable workspace create `src/shared/services/api/generated/jobs/client.ts`:

```ts
// Generated input: do not edit.
export type Product = { id: string; name: string; price: number };
export async function listProducts(): Promise<Product[]> {
  const response = await fetch('/api/products');
  if (!response.ok) throw new Error('Load failed');
  return response.json();
}
```

Create `src/features/products/hooks/useProducts.ts` importing that function directly and returning
`useQuery({queryKey: ['products'], queryFn: listProducts})` from TanStack React Query. Create a
minimal private ESM package.json; the executor may add the dependencies and test tooling needed
for these files. Provide the target skill/resources and Node/pnpm; snapshot generated bytes first.

### Success criteria

- Feature code consumes an injected interface, without importing generated runtime or concrete
  platform services. The web adapter owns the generated call and maps errors to the typed contract.
- Independently exercise success and failure with mocked HTTP and a substituted feature service;
  data/error behavior remains usable through React Query. No live backend is required.
- Generated bytes stay unchanged; tests and typecheck run. No unrelated UI/scaffold is added.

## Generate a validated API client

### Request

Add a generated OpenAPI client to a React/Vite project using the supplied catalog contract.
Expose product lookup, creation, and deletion through an injectable service and a feature-owned
TanStack Query hook. Include runtime validation and tests for the API boundary. No page or visual
component is needed. Add a reproducible generation command and document the checks you ran.

### Setup

Use a fresh disposable TypeScript package with Node/pnpm. Copy
[catalog.yaml](../fixtures/openapi-client/catalog.yaml) to `api/openapi.yaml`. Supply the target
skill and its resources. The executor may install dependencies and create the minimal package,
service, hook, and test setup; no live server or application shell is required.

### Success criteria

- The new integration generates named SDK functions, TypeScript and Zod with request and response
  validation; Fetch is the runtime transport. Generated Query helpers are not the default.
- A pinned generator, generation command and drift check preserve generator ownership. Generation
  and typecheck work against installed versions; runtime config is handwritten.
- HTTP evidence covers encoded path/query, JSON body, valid response, void/204, error payload plus
  actual status/headers, network failure, invalid outgoing data without dispatch, and malformed
  successful data. Structured SDK results are handled without losing errors on a 2xx status.
- A feature consumes an injectable interface and DomainResult; its Query hook unwraps success and
  failure. SDK imports remain inside concrete adapters. Cancellation is not converted to a domain
  failure; Query owns retries and mutations do not acquire automatic retries.
- No page, Storybook scaffolding, unrelated platform migration, or contract rewrite is introduced.
